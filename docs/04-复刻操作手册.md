## 1. 复刻路线图

```
拿到仓库
  └─ ① 本地打开 index.html，确认页面无报错
       └─ ② 准备 4 个 Excel（2 订单池 + 2 问卷「表单填写」）
            └─ ③ 拖入上传 → 列映射确认（必填列全绿）
                 └─ ④ 填周期/期数/时间范围/参数（默认值即生产口径）
                      └─ ⑤ 开始审核 → 对照基准统计
                           └─ ⑥ 人工处理无效名单 → 导出 2 个 Excel 验收
```

## 2. 环境准备（5 分钟）

1. 安装最新版 Chrome 或 Edge（需要支持 `Blob.arrayBuffer()` 与 localStorage）；
2. 获取代码：
   ```powersShell
   git clone https://github.com/1echo2026/raffle-audit.git
   # 网络受限时用 443 端口 SSH：
   git clone ssh://git@ssh.github.com:443/1echo2026/raffle-audit.git
   ```
3. 无需 `npm install`、无需构建：仓库内 `assets/xlsx.bundle.js` 已包含全部第三方依赖；
4. 双击 `index.html` 直接打开，或在仓库根目录起静态服务器：
   ```powershell
   python -m http.server 8080
   # 访问 http://localhost:8080/
   ```
5. 打开 DevTools（F12）Console，确认无红色报错；依次点击顶栏「📖 使用说明」「📊 高经团队周进度核算」与工具栏「编辑话术模板」，三个页面均能正常打开。

## 3. 准备输入数据

### 3.1 审核主页 4 个文件

| 文件 | 必备列（别名见文档 02） | 工作表 |
| --- | --- | --- |
| 强基订单池.xlsx | 账号ID、真实姓名、加密手机号、订单ID、订单金额、支付时间、订单归属渠道、订单归属人工号 | 任意 |
| 升学订单池.xlsx | 同上 | 任意 |
| 进阶问卷.xlsx | 所中奖项、提交时间、真实姓名、出单手机号（基地、销售姓名建议有） | **表单填写** |
| 巅峰问卷.xlsx | 同上 | **表单填写** |

文件名建议带「强基 / 升学 / 巅峰 / 进阶」字样，槽位自动识别更准；识别错了可用槽位上的「移动到…」下拉纠正。

### 3.2 团队进度页 2 个文件（可选功能）

- 月目标表：高经团队 + 月目标（基地可选）；
- 有数看板 GMV 表：高经/团队 + 转化金额。

> 含客户手机号与姓名的真实数据**不纳入 git 仓库**（仓库只放代码）。复刻 89 期时，把当期原始表按上面结构放到本地任意目录即可，文件名与列名能被别名识别就行。

## 4. 执行审核（以仓库开发期实跑样例为基准）

### 4.1 基准样例输入（工作区曾使用的文件）

| 槽位 | 文件 |
| --- | --- |
| 强基订单池 | `10月强基订单池.xlsx` |
| 升学订单池 | `10月升学订单池.xlsx` |
| 进阶问卷 | `导入/90进阶问卷.xlsx` |
| 巅峰问卷 | `导入/90巅峰问卷.xlsx` |

### 4.2 参数设置

- 最低订单金额 `999`、有效渠道前缀 `grow_xcg_zhuanjs_xiaoshou`、巅峰门槛 `20000`（均为默认，不要改）；
- 周期名称、中奖期数、订单支付/问卷提交时间范围按当期实际填写（时间范围留空 = 不限）；
- 「审核单量排行」按需勾选，只影响排序不影响人数。

### 4.3 基准对照值（上述文件、默认参数下的实跑结果）

| 统计卡 | 基准值 |
| --- | --- |
| 提交（问卷总条数） | **78** |
| 进阶有效 | **40** |
| 巅峰有效 | **5** |
| 无效 | **33** |
| 重复剔除 | **0** |
| 强基有效订单 | **13** |
| 升学有效订单 | **1184** |

校验方法：审核完成后页面 6 张统计卡必须与上表逐项一致；任一不一致，按第 6 节排查。复现其它期数（如 89 期）时，用该期**历史导出的审核结果 Excel** 或历史存档统计作为对照基准，方法相同。

### 4.4 操作步骤

1. 4 个文件一次性全选拖入虚线框，等待四个槽位全部显示识别成功；
2. 弹出「列映射确认」时检查必填列状态全为已匹配（warning 只提示冲突不阻断），点 **✓ 确认并开始审核**；
3. 若提示「检测到与上次相同的文件」：复刻验证选 **否，全部重新审核**，避免沿用旧人工裁决；
4. 对照 4.3 基准值；
5. 在「无效名单」页签抽查 3 类按钮：✅ 通过（转入明细）、🕓 待审核（无效原因变为「待审核通过后补发奖品」，再点一次取消）、✏️ 修改（改 11 位手机号后保存，系统自动重新匹配）；
6. 在「中奖人员明细表」对一条记录点 ✕ fail，确认其回到无效名单且原因保留；
7. 点橙色 **⬇ 导出（选择导出内容）**，勾选两个文件后 **导出所选**。

## 5. 验收清单

### 5.1 审核结果文件

| 验收项 | 预期 |
| --- | --- |
| 文件 1 | `第N期有效订单池.xlsx`，含「强基」「升学」两个子表，行数 = 统计卡强基/升学有效订单数 |
| 文件 2 | `第N期中奖名单审核结果.xlsx`，含 5 个子表：获奖名单图片格式、中奖明细（奖品底表）、宠粉数据总结、异常名单沟通话术、单量审核名单 |
| 获奖名单图片格式 | 巅峰按 1～4 等奖、进阶按 1～8 等奖分组；标题含周期名称 |
| 中奖明细 | 人数 = 进阶有效 + 巅峰有效；fail 退回的人不在其中 |
| 宠粉数据总结 | 左红巅峰 / 右绿进阶，8 行指标（出单数/出单人数/参与人次/参与人数/实际参与人次/两个人数参与率/人次参与率），参与率为百分比格式 |
| 沟通话术 | 无效 + 重复 + 含退款换课备注的有效行；待审核行「报备审核」列为「待审核通过补发」 |
| 文件名期数 | 与参数「中奖期数」一致 |

### 5.2 页面交互

- 刷新页面后参数恢复（`raffle_param_inputs_v1`）；
- 重新审核同组文件选「沿用上次记录」，人工裁决恢复且处理过的行淡紫色；
- 生成绿色通道码 → 在问卷手机号栏填该码、或在姓名/昵称后备注该码（如「张三 8K3D92AB」）的记录都自动放行，姓名中的码会被剥离；
- 话术模板页增删改后回主页，沟通话术自动套用新模板。

### 5.3 团队进度页（如复刻该功能）

- 上传月目标 + GMV 两表 → 开始核算，排名按完成度降序、第一名带 🏆；
- 周目标 = 月目标 ÷ 当月天数 × 本期天数；修改天数后结果联动；
- 导出 Excel 行数与页面团队数一致；月目标保存后刷新仍在，「清除已保存」需两次确认。

## 6. 常见故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| 弹窗「列映射失败，缺少必需列：X」 | 表头不在前 10 行或列名差异过大；在列映射弹窗手动指定该字段对应列，指定关系会被记住 |
| 统计卡人数与历史结果差几条 | ① 时间范围与历史口径不一致；② 沿用了旧人工裁决（重跑时选「全部重新审核」）；③ 订单表新增/删除了行；④ 渠道前缀被改动 |
| 大量「手机号在订单池中查找不到」 | 订单池加密手机号列识别错列；打开列映射确认检查「加密手机号」字段 |
| 撞号全部转待审核 | 问卷缺「销售姓名」列或该列没填；补齐后重跑，二次匹配可自动唯一命中 |
| 宠粉总结参与率为 0 | 问卷行没有匹配上有效订单（检查渠道是否全为非销售直推）或工号列为空 |
| 刷新后绿码/存档/模板丢失 | 清过浏览器站点数据或换了浏览器；这些数据只在本机 localStorage，导出 Excel 才是落盘 |
| 导出无反应 | 浏览器拦截了多文件下载；地址栏允许该站点的自动下载后重试 |
| 页面空白、Console 报脚本错误 | 确认 `assets/` 目录完整（4 个 JS + 1 个 CSS），且未用 IE 打开 |
| 时间过滤不符合预期 | 工具按本地时间解析 `yyyy-MM-dd HH:mm:ss`；检查 Excel 单元格是否真的是时间而不是文本 |

## 7. 无界面自动化验证（给开发同学）

核心算法无 DOM 依赖，可在 Console 或自动化脚本里直接驱动。最小示例：

```js
// 1. 用 SheetJS 读本地文件为二维数组（file 为 <input type=file> 拿到的 File）
const buf = await file.arrayBuffer();
const wb = XLSX.read(buf, {type:'array'});
const rows = XLSX.utils.sheet_to_json(wb.Sheets[wb.SheetNames[0]], {header:1, raw:false});

// 2. 构造与 app.js auditInput() 同构的输入
const result = AuditCore.audit({
  rawOrders: { qiangji: qjRows, shengxue: sxRows },
  questionnaire: { '进阶': jjRows, '巅峰': dfRows },
  distribution:  { '进阶': [], '巅峰': [] },
  params: {
    minAmount: 999, threshold: 20000,
    channelPrefix: 'grow_xcg_zhuanjs_xiaoshou',
    period: '9.9-9.16', qishu: '89',
    orderStart: '', orderEnd: '', formStart: '', formEnd: '',
    greenCodes: []
  },
  columnOverrides: { qjRaw:{}, sxRaw:{}, jjForm:{}, dfForm:{} }
});

// 3. 断言基准值
console.log(result.stats);
// { submitted:78, valid:45, validJJ:40, validDF:5, invalid:33, duplicates:0, ... }
```

页面还暴露了 `window.App`（`handleFiles/run/getResult/greenApprove` 等）与 `window.TeamProgress`（`loadGoal/loadGmv/run/getResult`），可用于端到端自动化，接口清单见文档 01 第 7 节。

## 8. 发布复刻版本

1. 改动后本地按第 4～5 节完整回归一遍；
2. 提交（约定身份）：
   ```powershell
   git add -A
   git -c user.name=audit-tool -c user.email=audit-tool@users.noreply.github.com commit -m "feat: 变更摘要"
   git push origin main
   # 受限网络：git push ssh://git@ssh.github.com:443/1echo2026/raffle-audit.git main
   ```
3. 等待 30～60 秒，用 `?ts=<时间戳>` 访问线上地址做缓存绕过校验；
4. 不要把真实客户 Excel、临时探针页面（`__*.html`）提交进仓库；`.gitignore` 已忽略 Office 临时文件。
