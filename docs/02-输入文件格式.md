# 02 · 输入文件格式（列名 / 别名 / 必填项）

> 所有输入均为 `.xlsx` / `.xls`。工具不写死列下标，而是在每个工作表**前 10 行内扫描表头**，按别名表识别列；识别不到必填列会中止并提示字段名，也可以在「列映射确认」弹窗里手动指定。

---

## 1. 输入文件总览

### 1.1 审核主页（4 个文件，可一次性全选拖入）

| 槽位 | 角色 | 工作表要求 | 识别提示 |
| --- | --- | --- | --- |
| 强基订单池 | 订单表 `order` | 任意工作表，含订单表头 | 文件名含「强基」优先入此槽；否则按列数等特征兜底 |
| 升学订单池 | 订单表 `order` | 同上 | 文件名含「升学」优先入此槽 |
| 进阶奖池问卷 | 问卷表 `form` | 取名为 **表单填写** 的工作表 | 文件名含「巅峰」→ 巅峰槽，其余 → 进阶槽 |
| 巅峰奖池问卷 | 问卷表 `form` | 同上 | — |

- 问卷文件里的「**发放情况**」工作表会被识别但**不参与审核**，无需提供；
- 一个 Excel 内有多张工作表时，按"命中字段数 × 2 + 表名提示加分 − 必填缺失 × 3"打分，每个槽位只保留置信度最高的候选；
- 槽位识别后仍可在页面上用「移动到…」下拉手动调整。

### 1.2 高经团队周进度页（2 个文件）

| 上传区 | 必需的两列 | 说明 |
| --- | --- | --- |
| 高经团队月目标表 | 团队列 + 月目标列 | 同名团队多行时目标自动累加；可保存锁定在本机 |
| 有数看板 GMV 表 | 团队列 + 转化金额列 | 明细行按团队聚合金额与单数 |

## 2. 通用表头识别机制（先读这节，再看别名表）

代码位置：`audit-core.js` 的 `normHeader()` / `resolveColumnMap()` / `findHeaderRow()`；团队页对应 `team-progress.js` 的同名函数。

1. **表头行扫描**：只看工作表前 10 行，命中任一必填字段别名即成为候选行，命中字段越多得分越高，取得分最高的一行；
2. **表头文字归一化**：去除全部空白（含全角空格）、去除各类括号与标点（`（）()【】[]：:、,，.。/-_~` 等）、转小写后再比对，因此 `加密手机号（掩码）` 与 `加密手机号(掩码)` 等价；
3. **两级匹配**：先做归一化后**完全相等**匹配，匹配不到再做**包含**匹配；
4. **列冲突处理**：两个字段命中同一列时，按字段定义顺序先到先得，并在列映射弹窗给出 warning；
5. **手动覆盖**：「列映射确认」里手动指定的对应关系按**表头文字**记忆（`raffle_colmap_v1`），下次同类文件自动复用；
6. **必填列缺失**：直接抛错中止审核，错误信息列出具体字段名，不会静默算错。

订单表的过滤口径（代码 `filterPool()`）：

- 账号ID 为空的行跳过；
- 订单金额 < 最低金额（默认 999）→ 剔除并计数 `rejAmount`；
- 支付时间不在配置范围内 → 剔除并计数 `rejTime`；
- 加密手机号格式无效 → 行保留、金额照算，但计入 `noPhone` 并在导出/日志中提示。

| 字段 key | 界面标签 | 必填 | 可识别的列名别名 | 用途 |
| --- | --- | --- | --- | --- |
| `nickname` | 用户昵称 | 否 | 用户昵称、昵称 | 展示与查找；整行空值判定用 |
| `avatar` | 用户头像 | 否 | 用户头像、头像、头像图片 | 仅在提供发放表时做头像校验，当前流程可缺 |
| `prize` | 所中奖项 | ✅ | 所中奖项、中奖奖品、奖品、奖项 | 解析奖品等级与名称（见 4.1） |
| `submit_time` | 提交时间 | ✅ | 提交时间、填写时间 | 问卷时间范围过滤、去重保留最早一条 |
| `base` | 基地 | 否 | 您的真实基地、真实基地、基地、所属基地 | 名单分组与导出 |
| `sales_name` | 问卷销售姓名 | 否 | 销售姓名、销售顾问姓名、销售顾问、您的销售姓名、出单销售姓名、顾问姓名、ccid、CCID、销售 | **掩码撞号时的二次匹配键** |
| `real_name` | 真实姓名 | ✅ | 您的真实名字、真实名字、真实姓名、姓名 | 获奖名单姓名 |
| `phone` | 出单手机号 | ✅ | 出单用户手机号/ID、出单用户手机号、出单手机号、手机号 | 填 11 位手机号参与匹配；填绿色通道码则直接放行（码也可以备注在真实姓名/昵称后面，同样自动放行并从姓名中剥离） |

问卷行解析要点（`loadQuestionnaire()`）：

- 手机号用正则 `1\d{10}` 提取，匹配不到则保留原值并标记 `phone_format_ok=false`（最终归为「手机号格式不正确」）；
- 每行获得稳定身份 `form_i`：进阶问卷 = 行号，巅峰问卷 = 1000000 + 行号，编辑/人工裁决按此锚定，不随排序漂移；
- 整行全空跳过；手机号为空的行**保留**（列为无效），避免人工修改清空后记录消失。

### 4.1 奖品文本解析规则（`parsePrizeText()`）

兼容 `一等奖：冰箱`、`一等奖 冰箱`、`1等奖·冰箱`、`一等奖冰箱` 等写法：

- 等级支持中文「一～十」与阿拉伯数字；
- 解析不出等级时不丢弃该行，按奖品名称聚合到「奖品」分组；
- 巅峰池按 1～4 等奖分组，进阶池按 1～8 等奖分组。

## 7. 最小可接受输入清单（复刻时照此准备）

**审核主页**（缺一不可，缺文件时点「开始审核」会弹窗提示）：

1. 强基订单池：含 账号ID、真实姓名、加密手机号、订单ID、订单金额、支付时间、订单归属渠道、订单归属人工号；
2. 升学订单池：同上；
3. 进阶问卷「表单填写」：含 所中奖项、提交时间、真实姓名、出单手机号（基地/销售姓名建议有）；
4. 巅峰问卷「表单填写」：同上。

**团队进度页**：

1. 月目标表：团队列 + 月目标列（基地可选）；
2. GMV 表：团队列 + 转化金额列。

列名不必与别名完全一致——归一化后能命中包含关系即可；命中不了时用「列映射确认」手动指定一次，之后浏览器会记住。
