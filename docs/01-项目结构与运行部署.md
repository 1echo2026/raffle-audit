# 01 · 项目结构与运行部署

> 适用仓库：`1echo2026/raffle-audit`
> 线上地址：<https://1echo2026.github.io/raffle-audit/>
> 文档目标：让新接手的同学拿到仓库后，能看懂每个文件的职责、把工具在本地跑起来、并完成线上发布。

---

## 1. 项目定位

中奖名单审核工具是一个**纯静态网页工具**（无后端、无构建步骤、无 npm 依赖），完成三类工作：

1. **名单审核**（主页）：上传 2 个订单池 + 2 个抽奖问卷 Excel，浏览器本地完成有效订单过滤、加密手机号归属匹配、按工号累计逐单判定进阶 / 巅峰奖池、去重与异常分流，并导出审核结果；
2. **话术模板管理**（独立页）：维护异常名单沟通话术，模板保存在本机浏览器；
3. **高经团队周进度核算**（独立页）：上传月目标表与有数看板 GMV 表，按团队折算周目标并排名导出。

所有 Excel 解析与计算均在浏览器本地完成，**文件内容不上传任何服务器**。

---

## 2. 技术栈

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 页面 | 原生 HTML + CSS + JavaScript（ES5 风格 IIFE） | 无框架、无编译、无 package.json |
| Excel 读写 | `assets/xlsx.bundle.js`（xlsx-js-style 1.2.0-beta，SheetJS 社区版带单元格样式的分支） | 本地打包进仓库，不依赖 CDN |
| 存储 | 浏览器 `localStorage` | 参数、列映射、历史存档、绿码、话术、月目标等全部本机持久化 |
| 托管 | GitHub Pages（静态托管） | 根目录 `.nojekyll` 保证所有文件原样发布 |
| 浏览器要求 | 现代 Chrome / Edge（推荐） | 用到 File API、`file.arrayBuffer()`、Blob 下载、localStorage |

## 3. 目录结构与文件职责

```
raffle-audit/
├── index.html              审核主页：上传区、参数区、结果区、全部弹窗的 DOM
├── templates.html          话术模板管理页（独立页面）
├── team-progress.html      高经团队周进度核算页（独立页面）
├── 使用说明.html            面向业务同学的图文操作手册（配 使用说明-img/ 截图）
├── README.md               仓库入口说明（索引 docs/ 下的复刻文档）
├── .nojekyll               告诉 GitHub Pages 不要走 Jekyll 处理
├── .gitignore              忽略 Office/系统临时文件
├── assets/
│   ├── xlsx.bundle.js      第三方库：Excel 解析与导出（含样式），勿手改
│   ├── style.css           全站样式与天蓝主题令牌（--blue / --sky-100 等）
│   ├── audit-core.js       审核核心逻辑（纯函数、无 DOM 依赖），可独立复用/测试
│   ├── app.js              审核主页 UI 层：文件识别、弹窗、人工裁决、表格渲染、Excel 导出
│   ├── templates-core.js   话术模板常量与 localStorage 读写（主页与模板页共用）
│   └── team-progress.js    高经团队周进度核算页全部逻辑
├── 使用说明-img/            图文手册的 19 张界面截图
└── docs/                   本复刻指南（01～04 四份文档）
```

### 3.1 三个页面的入口关系

```
index.html（审核主页）
   ├── 顶栏「📖 使用说明」   → 使用说明.html
   ├── 工具栏「编辑话术模板」→ templates.html
   └── 顶栏「📊 高经团队周进度核算」→ team-progress.html
```

### 3.2 脚本加载顺序（决定全局对象可用性）

| 页面 | 加载顺序 |
| --- | --- |
| index.html | `xlsx.bundle.js` → `audit-core.js` → `templates-core.js` → `app.js` |
| templates.html | `templates-core.js`（不需要 Excel 库） |
| team-progress.html | `xlsx.bundle.js` → `team-progress.js` |

各脚本通过 IIFE 挂全局对象，**没有模块系统**：

| 全局对象 | 定义位置 | 职责 |
| --- | --- | --- |
| `window.AuditCore` | audit-core.js | 列映射、表头识别、`audit(input)` 主流程、工具函数（`maskPhone` / `parseDt` / `fmtMoney` / `classifyAbnormal` 等） |
| `window.TplCore` | templates-core.js | 默认话术模板、`load()` / `save()` |
| `window.App` | app.js | 暴露给自动化自测的接口（`handleFiles` / `run` / `getResult` / `greenApprove` 等） |
| `window.TeamProgress` | team-progress.js | 团队进度页自动化接口（`loadGoal` / `loadGmv` / `run` / `getResult` 等） |
| `window.XLSX` | xlsx.bundle.js | SheetJS 读写 API |

### 3.3 分层约定（改代码前必读）

- **audit-core.js 是纯逻辑层**：输入二维数组 + 参数，输出结果对象，不碰 DOM、不读 localStorage（绿码列表由 app.js 作为参数传入）。业务口径改动只在这里做。
- **app.js 是 UI 层**：负责文件读取、调用 `AuditCore.audit()`、人工裁决（`overrides`）、渲染与导出。导出 Excel 的列顺序、样式、文件名都在这一层。
- **templates-core.js 是共享常量层**：默认话术模板只在此维护一份，主页与模板页共同读取，避免两处漂移。
- 命名约定：核心数据用下划线字段（如 `form_i`、`invalid_reasons`、`expected_pool`），DOM id 用驼峰（如 `btnRun`、`colMapModal`），localStorage 键统一 `raffle_<域>_v<版本号>`。

## 4. 本地运行

### 4.1 方式一：直接双击打开（最快）

直接用 Chrome / Edge 打开 `index.html` 即可，全部功能可用（Excel 读取走 `file.arrayBuffer()`，本地文件允许）。

> 注意：Chrome 对 `file://` 页面间的 iframe 跨帧访问有限制，但本工具页面间用普通链接跳转，不受影响。

### 4.2 方式二：静态服务器（更接近线上环境）

任选其一在仓库根目录启动：

```powershell
# Python（本机有 Python 时）
python -m http.server 8080

# 或 Node（本机有 Node 时）
npx serve .
```

浏览器访问 <http://localhost:8080/>。

### 4.3 浏览器能力清单

| 能力 | 用途 | 不支持时的表现 |
| --- | --- | --- |
| File / Drag-and-Drop API | 点击或拖入 4 个 Excel | 无法选择文件 |
| `Blob.arrayBuffer()` | 读取文件内容 | 上传即报错 |
| localStorage | 参数 / 存档 / 绿码 / 话术 / 月目标持久化 | 刷新后设置丢失，审核本身仍可跑 |
| `XLSX.writeFile`（Blob 下载） | 导出两个 Excel | 无导出文件 |
| `navigator.clipboard`（可选） | 复制绿色通道码 | 复制按钮静默失败，可手动选中复制 |

## 5. GitHub Pages 发布流程

仓库已开启 Pages，源为 `main` 分支根目录，**推送即发布**，无需构建。

### 5.1 常规发布

```powershell
# 1. 在仓库目录查看变更
git status

# 2. 暂存并提交（仓库约定的提交身份）
git add -A
git -c user.name=audit-tool -c user.email=audit-tool@users.noreply.github.com commit -m "feat: 变更摘要"

# 3. 推送（常规网络）
git push origin main
```

### 5.2 网络受限时：走 443 端口 SSH

当 `github.com:22` 被墙时，不改 remote，直接用完整 SSH URL 推送：

```powershell
git push ssh://git@ssh.github.com:443/1echo2026/raffle-audit.git main
```

### 5.3 发布后校验

- Pages 生效约需 **30～60 秒**；
- 校验静态资源时给 URL 加时间戳参数绕过缓存：`https://1echo2026.github.io/raffle-audit/?ts=<unix时间戳>`；
- 中文文件名（如 `使用说明.html`）访问时浏览器会自动做百分号编码，属正常现象。

### 5.4 为什么需要 `.nojekyll`

GitHub Pages 默认用 Jekyll 处理站点，会忽略下划线开头的文件/目录并做 Markdown 转换。根目录放置空文件 `.nojekyll` 后，仓库内容**原样发布**，保证 `assets/`、中文文件名与截图目录均可访问。

## 6. localStorage 数据清单（排查"换电脑数据没了"类问题）

| 键 | 写入位置 | 内容 |
| --- | --- | --- |
| `raffle_param_inputs_v1` | index.html 内联脚本 | 9 个参数输入框 + 单量排行勾选，填过即存 |
| `raffle_colmap_v1` | app.js | 四个槽位的手动列映射（字段 → 表头文字） |
| `raffle_history_v1` | app.js | 历史审核存档（最多保留 15 条，含快照与统计） |
| `raffle_last_filesig_v1` | app.js | 最近一次审核的文件签名（四个文件名排序拼接） |
| `raffle_last_manual_v1` | app.js | 最近一次人工裁决（通过 / fail / 待审核 / 话术修改），未手动存档也不丢 |
| `raffle_green_codes_v1` | app.js | 首页生成的绿色通道码数组 |
| `raffle_colwidths_v1` | app.js | 各结果表手动拖拽后的列宽 |
| `raffle_templates_v3` | templates-core.js | 话术模板（含默认模板的用户增删改） |
| `raffle_team_goal_v1` | team-progress.js | 高经月目标表（团队 + 目标，保存后锁定） |

> 这些数据**只存在当前浏览器的当前站点下**；换浏览器、换电脑、清除站点数据都会丢失。重要审核结果务必用导出按钮落 Excel。

## 7. 自动化 / 二次开发接口

页面在 `window` 上暴露了自测接口，可在 DevTools Console 或自动化脚本中调用：

```js
// 审核主页
await App.handleFiles(fileList);   // 注入 File 列表，自动识别四个槽位
App.run();                         // 等价于点「开始审核」（会先走列映射弹窗逻辑，需配合 UI 确认）
App.getResult();                   // 取最近一次 AuditCore.audit 的结果对象
App.greenApprove(form_i);          // 模拟无效名单「通过」
App.getColMap(); App.setColMap(m); // 列映射读写

// 团队进度页
await TeamProgress.loadGoal(file);
await TeamProgress.loadGmv(file);
TeamProgress.run();
TeamProgress.getResult();
```

核心算法的无 DOM 复用方式：构造 `auditInput()` 同构对象（见 [03-业务规则与计算口径.md](./03-业务规则与计算口径.md) 第 2 节），直接调用 `AuditCore.audit(input)` 即可得到完整结果对象。
